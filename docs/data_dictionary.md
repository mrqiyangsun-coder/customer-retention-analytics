# Analysis database: version 1

Source: `data/processed/retail.sqlite`, generated by `clean.py`. Monetary values are GBP as recorded. See `cleaning_rules.md` before interpreting any total.

| Table/view | One row represents | Key/use |
|---|---|---|
| transactions | A retained original invoice line, with parsed fields and line classification | `(source_sheet, source_row)` locates the original Excel row |
| export_exclusions | A repeated exported line removed from cross-sheet double counting | Original source key plus exclusion reason |
| purchase_lines (view) | A transaction classified as a qualifying positive purchase line | Use for positive recorded line-value analysis |
| orders | One qualifying invoice | `invoice_no`; `order_value` sums positive qualifying lines |
| customer_orders (view) | An order with exactly one unambiguous customer identity | Use for identified-customer histories |
| customers | One observed identified customer | `customer_id`; first/last observed order, observed order count and positive value |
| monthly_sales | A calendar month with qualifying orders | `month`; complete-month flag is only an observed-span check |
| pipeline_metadata | One pipeline fact encoded as JSON | Rules version, source checksum, counts and coverage |

## Important fields

- `source_row`: Excel row number, starting at 2 after the header.
- `line_type`: `purchase`, `adjustment`, `non_purchase` or `invalid_core`; these categories are mutually exclusive.
- `line_value`: quantity times unit price for core-valid records. Filter to purchase lines before using it as positive recorded sales.
- `order_date`: earliest qualifying line timestamp on an invoice.
- `customer_id_conflict`: 1 if an invoice has multiple distinct known customer IDs; the order's customer ID is then missing.
- `order_value`: positive recorded value; does not subtract later cancellation/adjustment lines.
- `first_observed_order`: earliest identifiable qualifying order in this dataset; not a proven acquisition date.
- `observed_orders`: distinct qualifying invoice count, not product-line count.
- `is_complete_month`: the whole calendar month fits inside the observed date span. It does not establish that there were no outages/missing exports.

Rows without identity remain available for sales analysis. Retention/cohort analyses use only identified-customer orders and must disclose that coverage difference. Do not combine raw `transactions` with `export_exclusions` for business totals; the exclusions exist for traceability.
